03

Connector Registry

Every workflow step touches an external system. The registry grounds each in reality — its API availability, consent rail, auth and regulatory constraints — and prescribes a fallback ladder wherever no API exists. Integrate, don't recreate.

Global fallback ladder. official API → partner/aggregator API → authorised-portal automation → pre-filled forms + guided manual → document upload + OCR → reminder-only. A workflow is never blocked because an API is missing — every rung is logged, and the family always sees what remains manual.

Reality note

No universal write API

India has no open-banking write rail. Saarthi reads via AA and writes via NPCI mandates (UPI / e-NACH) and BBPS. Direct per-bank APIs are opportunistic partnerships.

Consent architecture

DPDP is the umbrella

DEPA/AA for finance, ABDM for health, DigiLocker for documents — each pull maps to a DPDP purpose and writes a consent_ref into the Twin. Revocation tombstones dependent data.

Designed to retire

Ready for Bima Sugam

Insurance is portal-heavy today; per-insurer and per-TPA connectors are modelled so emerging rails — Bima Sugam, ONDC, OCEN — can subsume the scraping fallbacks without touching workflows.

AI Architecture & Assurance

For a system that moves money, files with governments and touches health, "usually right" is not a bar. Accuracy is primarily an architecture property, not a model property — AI is deliberately contained, and deterministic systems carry the guarantees. A hallucination degrades to a suggestion a human declines, never a wrong transfer.

How it's powered

Router · agents · grounded memory

A LiteLLM gateway routes each task to GLM / Qwen / Llama / DeepSeek / Gemma with automatic fallback; regulated data runs on self-hosted vLLM in-region. A planner decomposes each responsibility to ~12 domain specialists on a checkpointed graph.

Memory is separate from the model: working & long memory → the Digital Twin → vector search → knowledge graph. GraphRAG grounds every answer in the family's actual entities — the model retrieves facts, it never recalls them from weights.

The containment model

Five layers, boxing the LLM

1 · Execution boundary

engine executes, LLM only proposes; approval gate on every mutating step

2 · Structured output

typed, schema-validated against the Twin; malformed → reject & retry

3 · Grounding + provenance

facts cite a Twin entity + consent_ref; ungroundable claims flagged

4 · Determinism

tax, EMI, capital-gains, premiums in code — never LLM arithmetic

5 · Abstention

below a confidence threshold, escalate to a human — don't guess

How we prove it — golden-set evaluation, in CI

Each workflow ships a labeled dataset of real-shaped cases with known-correct outcomes — that's why the catalog specifies inputs and outcomes so precisely. Every prompt, model or router change runs the affected sets in CI; a regression blocks merge. Targets are tier-dependent:

Before production

Shadow, then canary

New capability runs in observe mode — predict, don't act — against live traffic, compared to what humans did; domain experts sign off on high-stakes lanes before any autonomy.

In production

Traced & drift-watched

Langfuse / Phoenix trace every step; live accuracy is a metric. Drift demotes a workflow's automation level automatically, and the router fails over to a known-good model.

The closing loop

Learns from every "no"

Declined or modified suggestions — with their reason, volunteered or briefly asked — are captured from day one: immediate per-family preferences (reversible, via retrieval) plus a de-identified stream for governed model improvement. Sustained acceptance raises earned autonomy; declines lower it.

Content is data, not instructions. Bill PDFs, connector responses, portal and OCR text are untrusted input — agents can't be redirected by injected content, and any content-driven attempt to escalate access or take an unexpected action is refused or escalated. Credentials never enter a prompt or the graph.

Built so scale is additive, not a rewrite

The operational contract exists so no phase forces a structural change. Twelve decisions are locked from the first prototype; everything after is additive — new workflows, connectors, plans and personas slot into existing structure.

Platform · 07

Kubernetes-native, multi-tenant

Stateless services on K8s; family_id as a hard partition from day one; India-region storage for regulated data; autoscaling, HA, tested DR with per-phase RPO/RTO targets.

Identity · 08

Persona-wise login

Identity plane separate from Person; passkeys/MFA with step-up before any money movement or filing; ABAC over the Twin at one enforcement point; delegation & audited break-glass for caregivers.

Billing · 09

Trial → autopay → lock

Monthly/annual plans; autopay (UPI AutoPay / e-NACH / card) set up and pre-scheduled before the trial ends; single-point entitlement gating; locking never holds a family's own data hostage.

Security · 10

Zero-trust & compliant

Encryption + per-tenant keys, secrets vault, card data never stored (PCI-scoped); DPDP rights, RBI/AA, IRDAI, ABDM mapped to engineered controls with an immutable audit log.

What's still open is tracked, not hidden. A living gap register (doc 06) names every unspecified area — notification service, mobile/web architecture, analytics, admin console, and the Preparedness/Trust score formulas — with the document that will own each.
